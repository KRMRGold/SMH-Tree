## Architecture and invariants

- SQLite is the canonical store; no ORM.
- IDs and timestamps are generated by Python, not SQLite.
- Branch messages are append-only. Forking stores a parent branch and fork-message reference; it does not copy history.
- A branch's visible history is its own messages plus the inherited path ending at its fork message. Sibling messages and parent messages appended after a fork are excluded.
- Every API route requires the per-launch bearer token.
- API is intended to bind to loopback only; desktop process supervision is not implemented until M8.

## Known limitations

- No chat provider or streaming chat yet (M2).
- No memory services, scope enforcement, context compiler, or epistemic API yet (M4–M6).
- No desktop shell, remote gate, or packaging yet (M3 and M8–M9).
- The M0 candidate tag was intentionally omitted with user acceptance. Future candidate tags remain part of the workflow unless separately accepted as an exception.
- M0's local verification used Python 3.13.5; the authoritative Python 3.12.16 CI run passed.
